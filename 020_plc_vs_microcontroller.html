PLC vs マイコン

産業用「当たり前」をマイコンで分解して理解する

「脳」を切り替える

PLC (産業用)

産業用PC

工場の過酷な環境（ノイズ・熱）に耐える、完成されたシステム。

  • 壊れないことが最優先
  • OSとハードが一体化
  • 配線すれば動く「ブラックボックス」
マイコン (汎用)

意志あるチップ

ESP32等の小型チップ。自由度が極めて高いが、全て自分で組む必要がある。

  • 安価でどこにでも組み込める
  • 回路もソフトも自作
  • 「中身が見える」から面白い

プログラムはどう動く？

スキャン方式

全行を高速周回

1行目から最終行までを読み取って1周。これを永遠に繰り返す。

全ての入力状態が毎サイクル同期される

逐次実行

1行ずつ順番に

書いた順番通りに上から下へ進む。最後まで行ったら終わり。

print("A")
if button.value():
    print("B")
# ここで止まる（ループしない）

「ループ」は誰が作る？

PLC

自動ループ

ハードウェア/OS側で自動的にループ処理が行われる。

  • 開発者は「中身」だけ書けばいい
  • 止めるには「STOP」スイッチが必要
マイコン

意志あるループ

自分で while True: 等を書き、意図的に無限ループを作る。

while True:
    # ここに処理を書く
    # ループも自分で制御する

爆速CPU vs 現実のスイッチ

マイコン（CPU）は速すぎる。物理スイッチが押された瞬間の「バタつき」さえも拾ってしまう。

チャタリング現象

スイッチが「ON」になる瞬間、物理的には数百μsの間、激しくON/OFFを繰り返している。

対策：ソフトウェア処理

マイコンでは time.sleep(0.02) 等で「バタつき」が収まるのを待つ必要がある。

※PLCではこの処理は内部で自動的に行われている！

不定状態（フラフラ）を防ぐ

スイッチが押されていない時、ピンの電圧はどうなるか？

PLC：当たり前の安定

内部回路でプルアップ/プルダウンが完結している。ユーザーは気にする必要がない。

マイコン：プルアップ抵抗

何もしないと「0でも1でもない不安定な状態」になる。内蔵抵抗を有効にする等の設定が必須。

pin = Pin(14, Pin.IN, Pin.PULL_UP)

まとめ：PLC vs マイコン

比較項目 PLC (シーケンス制御) マイコン (Python/ESP32)
実行方式 スキャン方式（全行高速周回） 逐次実行（1行ずつ順番に）
ループ 自動（OSが回す） 手動（while True 等）
入力の安定化 自動（ハード側で処理） 手動（コードや設定で書く）

→ マイコンは「自由度が高い」からこそ、仕組みの理解が重要！
